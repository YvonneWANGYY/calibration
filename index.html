Getting started

Install the software once and define your calibration problem. Then choose how to start: generate a Latin hypercube design or reuse simulations you have already completed.

Install and create a project

Use Python 3.10 or newer and Git. These shell commands install the public release in a virtual environment on Linux or macOS.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install 'git+https://github.com/YvonneWANGYY/calibration.git@v0.2.0'
mkdir my-problem
curl -fsSL https://yvonnewangyy.github.io/calibration/guide/heat/problem.json -o my-problem/problem.json
curl -fsSL https://yvonnewangyy.github.io/calibration/guide/heat/simulate.py -o my-problem/simulate.py

The new directory contains problem.json and a working simulate.py. Run the remaining shell commands from its parent directory.

Set up the calibration problem

Both workflows use the same parameter ranges, target profile, simulator command, and adaptive iteration count in my-problem/problem.json.

What is a target profile?

A target profile describes what you want the simulator to reproduce. Choose the output you want to match, where to compare it, and the value you want it to take at each point. Use the same reference for every parameter set, whether your first simulations are imported or newly generated.

In the paper, θ denotes the inputs you can adjust, c is the set of quantities measured in one simulation, and c★ contains their desired values. A completed simulation gives one pair (θ, c). The paper’s conditional neural spline flow (Durkan et al. 2019) learns from these pairs and proposes new inputs for the desired c★. A loss then summarizes how closely a completed run matches the reference.

Example: how far does heat travel along a rod?

A 10 cm rod starts at 20 °C. A heater holds its left end at a constant temperature while its right end stays at 20 °C. The simulator divides the rod into cells and advances the heat equation for 60 seconds. You can change two inputs: the heater temperature and the thermal diffusivity, which controls how quickly heat spreads.

Your target is a temperature profile. At 60 seconds, you want the simulation to match temperatures at three positions along the rod. For this tutorial we generated those target readings using a finer reference simulation (200 cells, diffusivity 0.09 cm²/s, heater 80 °C) and rounded them to two decimals. Every trial uses 100 cells.

Read one trial. With the heater at 80 °C and diffusivity at 0.04 cm²/s, too little heat reaches the interior. Increasing diffusivity would carry heat farther along the rod. The pipeline tries parameter pairs and compares the three simulated temperatures with the same three targets each time. The local loss is the sum of the three squared temperature differences.

For your own simulation, choose an output field, a sampling time, and the locations where you want to match it. Put the desired values in problem.json under target. Have your adapter return the simulated values under the same IDs. An imported results table uses those IDs as column names. Download the rod target profile · Read the heat solver

How the paper defines its targets

  • Sedov blast wave. At a fixed time, compare density, pressure, radial velocity, and transformed specific internal energy with the analytical blast-wave solution on a common radial grid (Taylor 1950). Each output is a simulated value minus its analytical reference, so the desired profile is zero at every radius. The reported error accounts for radial bin widths.
  • Rotating cylinder. The study uses the Enzo hydrodynamics code (Bryan et al. 2014). Track the change in each of the three angular-momentum components at 51 saved times, relative to the initial component value and scaled by the magnitude of the initial axial angular momentum. Conservation gives a target of zero drift in each component at every time.
  • SAGE galaxy formation. The SAGE galaxy-formation model is described by Croton et al. (2016). Its calibration targets are observations. For example, the study uses the galaxy number density in stellar-mass bins measured by Baldry, Glazebrook & Driver (2008). The adapter must apply the same bin definitions and logarithmic units to its predictions. The paper’s comparison score averages squared residuals within each observable after scaling by its observed range (mapped to [−1, 1]), then gives each observable equal weight. A densely sampled observable therefore gets the same total weight as a sparsely sampled one. Inspect the published SAGE target bins.

  ],
  "target": {
    "temp_1cm": 65.66,
    "temp_3cm": 41.68,
    "temp_5cm": 27.69
  },
  "simulator": [
    "{python}",
    "simulate.py"
  ],
  "initial_samples": 8,
  "adaptive_steps": 4,
  "candidate_pool_size": 256,
  "seed": 42
}

adaptive_steps is the number of new adaptive evaluations in either workflow. initial_samples sets the size of a newly generated design. When importing data, the rows in your CSV supply the initial evaluations.

Start from scratch

Latin hypercube sampling distributes points across the full range of each input by sampling once per stratum (McKay, Beckman & Conover 1979). With the example settings above, eight initial points and four adaptive proposals require twelve simulator calls. It ranks candidates using nearby measured losses and parameter-space distance.

autocalibration run my-problem/problem.json --output my-run

Use a fresh output directory for each run. candidate_pool_size controls how many parameter sets are considered per adaptive step. Only the selected set goes to the simulator.

Use existing simulations

Use the Python session API when you already have parameter values and measured outputs. The existing points can come from any design. Include one column for each parameter and one for each target ID. Download the example CSV as initial.csv alongside my-problem/.

Download initial simulations CSV

Save the following as continue_calibration.py beside the CSV and run python continue_calibration.py. It loads two completed evaluations and runs four new simulations through the same adapter. Append each completed row to the CSV to reuse it next time.

import csv
import json
from pathlib import Path
import subprocess
import sys

from autocalibration import AdaptiveCalibrationSession, ParameterSpec

project = Path("my-problem")
problem = json.loads((project / "problem.json").read_text())
params = [ParameterSpec(**p) for p in problem["parameters"]]
target = problem["target"]
session = AdaptiveCalibrationSession.from_files(
    params, target, metrics_file="initial.csv", metric_columns=list(target)
)
command = [sys.executable if arg == "{python}" else arg for arg in problem["simulator"]]

with open("initial.csv", newline="") as src:
    columns = csv.DictReader(src).fieldnames
with open("initial.csv", "a", newline="") as dest:
    writer = csv.DictWriter(dest, fieldnames=columns)
    for step in range(problem["adaptive_steps"]):
        point = session.recommend(1, candidate_pool_size=problem["candidate_pool_size"],
                                  seed=problem["seed"] + len(session.observations))[0]
        theta = point["parameters"]
        result = subprocess.run(command, cwd=project, input=json.dumps(theta),
                                capture_output=True, text=True, check=True)
        metrics = json.loads(result.stdout)
        session.add_observation(theta, metrics)
        writer.writerow({**theta, **{name: metrics[name] for name in target}})
        dest.flush()

losses = session.losses()
best = losses.index(min(losses))
print(session.observations[best].parameters, losses[best])

Connect your simulator

The adapter is the only model-specific piece. For each evaluation, the runner starts the configured command in the problem directory. The command reads a JSON parameter object on standard input, runs the model, and writes a JSON object of predictions on standard output.

Try one evaluation

printf '%s\n' '{"diffusivity_cm2_s": 0.04, "heater_c": 80}' | python my-problem/simulate.py

The example returns approximately {"temp_1cm": 58.896, "temp_3cm": 30.263, "temp_5cm": 21.348}. For your simulator, translate parameters into its native input format, wait for it to finish, and extract a finite value for each target ID. Send logs to standard error and exit with a nonzero status if the simulation fails.

Read the results

After a CLI run, inspect my-run/summary.json for the best evaluated parameters, their predictions, and the measured loss. evaluations.jsonl has one record per completed simulation, including those completed before an interruption.

The local runner sums squared differences across target IDs. If observables have different scales or units, scale predictions and targets consistently before comparing them. The adaptive acquisition score ranks candidates before simulation; the measured loss tells you how well a completed simulation matches the target.

Reproduce the SAGE paper results

The bundled SAGE study has its own commands. Replay the reported model selection and print the five- and eight-observable losses with:

autocalibration reproduce-sage

To try the paper’s conditional neural spline flow (NSF), install the flow extra and run the short first-round SAGE example:

python -m pip install 'fully-autonomous-calibration[flow] @ git+https://github.com/YvonneWANGYY/calibration.git@v0.2.0'
autocalibration propose-sage --smoke --output sage-first-proposal

Generic recipe launcher

A recipe declares the science target, parameter space, initial design, simulator wrapper, proposal model, run controls, and output identity, then the launcher materializes a dry-run command and optional manifest that can be wrapped by the user's own local scheduler. 

python scripts/launch_adaptive_calibration.py --recipe recipes/adaptive_calibration_template.json
# write your own scheduler wrapper around the printed command

Edit before running: replace the target file, parameter bounds, simulator wrapper, proposal-model root, and output label with your own calibration artifacts.

What users provide

Target, bounds, wrapper, and resources stay explicit.

This template makes the automation boundary visible: it standardizes the recipe-to-command interface while leaving the scientific target, simulator integration, initial design, and batch-system submission as researcher-defined inputs.

Local recommendation loop

Cold-start LHS, then iterative recommendations from metrics files.

The lightweight library in src/autocalibration lets a user start with only parameters, ranges, and a target profile. If no initial metrics exist, it returns the requested number of Cold-start LHS parameter vectors; after the user runs simulations, CSV, JSON, or optional HDF5 metrics files can be added for the next adaptive recommendations. 

session = AdaptiveCalibrationSession.from_files(
    parameters=parameters,
    target_profile="examples/sage_like_target_profile.json",
)
initial_runs = session.recommend(n=4, seed=1)
session.add_observations_from_file("examples/sage_like_initial_metrics.csv")
next_runs = session.recommend(n=2, seed=5)

Autonomous loop

A recipe materializes the run, then the loop advances itself.

The reusable engine combines conditional neural spline flow (NSF) proposal learning, acquisition, simulator execution, and bookkeeping into a closed-loop calibration run after the case-specific recipe is specified.

01Recipe

Target, bounds, wrapper interface, and initial design.

02Preflight

Validate paths, strategy, and output plan.

03NSF proposal

Fit a target-conditioned learned proposal from evaluated rows.

04Acquisition

Select the next parameter vector with ranking, MAP, or sampling.

05Simulation

Run the astrophysical model through the case wrapper.

06Update

Append metrics, manifests, and history for the next iteration.

Autonomy boundary

What "fully autonomous" means here

Autonomous means the closed-loop run proceeds after the recipe is specified. It does not mean the system invents the science target, parameter domain, simulator wrapper, PBS resource policy, or initial design. Those are researcher-defined inputs. The contribution is that the subsequent adaptive exploration, proposal fitting, acquisition, simulator dispatch, and run bookkeeping are encapsulated and reproducible.
