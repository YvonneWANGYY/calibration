Fully Autonomous Calibration for Astrophysics

Tune your simulation’s parameters to match a target within a limited simulation budget.

Quickstart ↓ Paper (in preparation) Code ↗ Cite

Use it when each simulation is expensive, several inputs are adjustable, and you can describe a good outcome. Your target might come from measurements, an analytical solution, or a conservation law.

You provide parameter ranges, target values, a simulator command, and a round budget. You receive the best run found, a separately evaluated final recommendation, and a record of every evaluation. If some runs require much more work than others, you can also account for predicted simulation cost when choosing the next inputs.

How it works

Parameters → Your simulator → Outputs → Learn → Next parameters ↻
  1. Start with completed simulations or generate an initial design spanning your parameter ranges.
  2. Fit models that learn which inputs tend to produce outputs near your target.
  3. Choose the next inputs. Early rounds favor exploration where models disagree. Later rounds favor promising regions the models agree on.
  4. Run your simulator, record its outputs, and repeat for the requested number of rounds.
  5. Refit using all evaluations, choose a final parameter set, and test it in one extra simulation.

Key terms

Parameters (θ)
Inputs you can change, such as heater temperature.
Outputs (c)
Quantities measured in one simulation.
Target (c★)
Desired values of those same quantities.
Loss
One number measuring the discrepancy. Lower is better.
Adaptive round
One cycle of learning, choosing inputs, and running the simulator.
Best observed
The evaluated run with the lowest measured loss.
Final recommendation
The last choice from the refitted model, tested in one extra simulation. An earlier run may fit better.
See Figure 1 and the method used in the paper

The paper fits conditional neural spline flows to simulation input–output pairs. Given the target, the ensemble draws and ranks candidate inputs. After the adaptive rounds it estimates the peak of the calibration density in physical parameter coordinates. See “Candidate Selection” in the manuscript. Durkan et al. (2019).

Quickstart · Heat a rod

Find a heater temperature and thermal diffusivity that reproduce the temperatures at three distances along a rod after one minute.

You need Python 3.10 or newer, Git, and a CPU. Our test took about six seconds after installation using one CPU thread. Installation time depends mainly on downloading PyTorch.

1. Install the software

python -m pip install 'fully-autonomous-calibration[tuning] @ git+https://github.com/YvonneWANGYY/calibration.git@v0.5.1'

2. Download the example

Download the heat example (ZIP) and extract it. Open a terminal in the heat-example folder beside simulate.py.

3. Run the calibration

autocalibration run new-design.json --output from-design

Use your own simulator

Copy either heat problem file and change four things. Keep "method": "neural_spline_flow" to use the flow workflow.

  1. Parameters. Give each adjustable input a name, lower bound, and upper bound. For positive values spanning orders of magnitude, logarithmic spacing gives each decade comparable coverage. For example, use {"name":"diffusivity","lower":0.001,"upper":1,"scale":"log"}. Use linear spacing when equal absolute increments make sense.
  2. Target. Under target, name each output and give its desired value. Use identical IDs in the simulator response and the imported CSV. Compare outputs at the same coordinates, time, and units.
  3. Simulator command. For a Python adapter, set "simulator": ["{python}", "simulate.py"]. The runner starts it in the problem file’s directory and sends one JSON object on standard input.
  4. Budget. Set adaptive_steps to the number of learn–select–run cycles. Budget for any newly generated initial runs and one final recommendation as well.
Python adapter template

Replace the import and call with your model’s interface. This example assumes the model returns temperatures keyed by distance in centimetres.

import json
import sys
from my_solver import simulate

parameters = json.load(sys.stdin)
temperatures = simulate(**parameters)
outputs = {f"temp_{x}cm": temperatures[x] for x in (1, 3, 5)}
print(json.dumps(outputs, allow_nan=False))

Print diagnostics to standard error. See the complete runnable heat solver.

See the illustrated target-profile example

A target profile describes what you want the simulator to reproduce. Choose the output you want to match, where to compare it, and the value you want it to take at each point. Use the same reference for every parameter set, whether your first simulations are imported or newly generated.

In the paper, θ denotes the inputs you can adjust, c is the set of quantities measured in one simulation, and c★ contains their desired values. A completed simulation gives one pair (θ, c). The paper’s conditional neural spline flow (Durkan et al. 2019) learns from these pairs and proposes new inputs for the desired c★. A loss then summarizes how closely a completed run matches the reference.

How far does heat travel along a rod?

A 10 cm rod starts at 20 °C. A heater holds its left end at a constant temperature while its right end stays at 20 °C. The simulator divides the rod into cells and advances the heat equation for 60 seconds. You can change two inputs: the heater temperature and the thermal diffusivity, which controls how quickly heat spreads.

Your target is a temperature profile. At 60 seconds, you want the simulation to match temperatures at three positions along the rod. For this tutorial we generated those target readings using a finer reference simulation (200 cells, diffusivity 0.09 cm²/s, heater 80 °C) and rounded them to two decimals. Every trial uses 100 cells.

Read one trial. With the heater at 80 °C and diffusivity at 0.04 cm²/s, too little heat reaches the interior. Increasing diffusivity would carry heat farther along the rod. The pipeline tries parameter pairs and compares the three simulated temperatures with the same three targets each time. The local loss is the sum of the three squared temperature differences.

For your own simulation, choose an output field, a sampling time, and the locations where you want to match it. Put the desired values in your problem file under target. Have your adapter return the simulated values under the same IDs. An imported results table uses those IDs as column names. Download the rod target profile · Read the heat solver

How the paper defines its targets
  • Sedov blast wave. At a fixed time, compare density, pressure, radial velocity, and transformed specific internal energy with the analytical blast-wave solution on a common radial grid (Taylor 1950). Each output is a simulated value minus its analytical reference, so the desired profile is zero at every radius. The reported error accounts for radial bin widths.
  • Rotating cylinder. The study uses the Enzo hydrodynamics code (Bryan et al. 2014). Track the change in each of the three angular-momentum components at 51 saved times, relative to the initial component value and scaled by the magnitude of the initial axial angular momentum. Conservation gives a target of zero drift in each component at every time.
  • SAGE galaxy formation. The SAGE codebase implements the galaxy-formation model described by Croton et al. (2016). Its calibration targets are observations. For example, the study uses the galaxy number density in stellar-mass bins measured by Baldry, Glazebrook & Driver (2008). The adapter must apply the same bin definitions and logarithmic units to its predictions. The paper’s comparison score averages squared residuals within each observable after scaling by its observed range (mapped to [−1, 1]), then gives each observable equal weight. A densely sampled observable therefore gets the same total weight as a sparsely sampled one. Inspect the published SAGE target bins.

Before you run

  • Test the simulator command with one input. Check that it exits successfully and prints a single JSON object with a finite number for every target ID.
  • Check the units and scale of each simulated output against its target. For imports, check parameter bounds and column names.
  • If your simulator is stochastic, choose how to handle its seed or average repeated runs inside your adapter. The runner records each returned value as one observation.
  • Use a new output folder. A failed evaluation stops the run. Completed rows remain in evaluations.jsonl.
Choosing a loss for outputs with different units

The local runner sums squared differences between the outputs and their targets. For temperatures in °C, the loss is in °C². For unlike quantities, apply the same scaling to each target and its simulated counterpart before returning them. Otherwise a large numerical range can dominate the loss.

The SAGE paper maps each observable’s observed range to [−1, 1], averages squared differences across that observable’s bins, then averages across observables. This gives equal weight to each galaxy property. See the SAGE comparison targets.

Assign a cost to each run

Adding a cost field changes the adaptive selection rule. The flow runner automatically applies a penalty of 0.1. To record cost and run a baseline, set "cost": false in the problem file.

You decide what “expensive” means. For each parameter choice, return one finite number called cost alongside your simulator outputs. Higher numbers mean more expensive. Use the same scale throughout a calibration. For example, the cost could be a fee, an amount of material, or your own difficulty score. Zero and negative scores are valid.

{"temp_1cm": 58.90, "temp_3cm": 30.26, "temp_5cm": 21.35, "cost": 7}
Simple mode · arbitrary expense scorePaper mode · positive resource measurement
Return a finite cost field from the first evaluation. Any sign is valid. Higher means more expensive.Set "cost": {"metric": "cpu_seconds", "beta": 0.1} in the problem file. Supply a strictly positive value under that metric name on every row.
The runner rescales observed costs to 0–1 each round. The score subtracts 0.1 times predicted scaled cost.The score subtracts β times the predicted log cost ratio relative to the measured cost of the lowest-loss run so far. This is the penalty used in the hydrodynamic studies.

When cost is optional. A CSV without costs works when the adapter also omits cost and paper mode is off. To enable simple mode with imports, add a numeric cost column to every imported row and return it on every subsequent call. Partial coverage fails: a missing field after enabling cost gives missing cost field 'cost'; adding it late gives supply cost from the first evaluation, including imported runs. Empty CSV cells cannot be parsed as numbers.

Cost versus target. Put the desired temperatures in target and the measured expense in the simulator response. Putting "cost": 7 inside target makes 7 a value to match in the loss and disables automatic cost detection. Explicit paper mode rejects a conflicting name with cost.metric must be separate from target and parameter names. A zero or negative paper-mode value stops the run with, for example, expected a positive measured cost in 'cpu_seconds'.

What happened in the heat example?

autocalibration run cost-aware.json --output from-cost

Our cheapest run used 528 solver steps (evaluation 7) and the most expensive used 1,818 (evaluation 6). To compare, copy cost-aware.json to no-cost.json, add "cost": false at the top level, and keep the same adapter, seed, and budget:

autocalibration run no-cost.json --output without-penalty

The two runs chose the same inputs in all 13 evaluations. Both used 15,430 solver steps in total, and both final tests used 929 steps with loss 13.77 °C². For this seed the simple penalty left the winning candidate unchanged in every round.

What the cost penalty can and cannot predict

  • The penalty shapes which simulations enter training during the adaptive search. The final recommendation is selected without a cost penalty, then evaluated to measure its actual cost and error.
  • A larger β can give a more expensive final pick. In the rotating-cylinder study, β = 1 gave about 6.5 times the conservation error of β = 0.1 and slightly higher refinement complexity.
  • Both modes use the 80th percentile of 500 trees’ predictions. Actual cost can exceed that estimate. Along the paper’s cost-aware searches, mean absolute percentage error was 3.6% for Sedov and 11.4% across the two rotating-cylinder runs.
How model tuning and candidate pools work

Optuna (Akiba et al. 2019) chooses flow settings using the lowest mean held-out negative log-likelihood. Set tuning.trials for search attempts, tuning.folds for validation groups, and tuning.epochs for training passes per fit. Both tuning schedules refit model weights each round. See the configurable search space.

In one SAGE comparison with the same initial simulations, the first new evaluation had five-observable loss 0.126 with 5,000 candidates, 0.080 with 10,000, and 0.340 with 20,000. Pool size changes which candidate wins the ranking, so increasing it need not improve the next simulation.

Results from the paper

The same selection loop was tested on a shock profile, a conservation law, and galaxy observations. Each test used its own physical measure of agreement. The hydrodynamic studies also used an optional simulation-cost penalty (β). Select paper mode in the local runner to use that log-ratio penalty. Try cost-aware selection in the heat example.

Scope of the results. Each adaptive configuration represents one search. The reported differences describe those runs. Independent starts can select different simulations.

Sedov blast wave

Each search used 26 simulations. Accounting for predicted cost gave a final recommendation with nearly the same shock-profile error as the search without a cost penalty (0.2855 versus 0.2860) and 54.7% less refinement complexity. In both searches an earlier simulation had lower error than the final recommendation.

Rotating cylinder

With a moderate cost penalty (β = 0.1), the final recommendation used 22% less refinement complexity than the best initial run, with 10% higher angular-momentum conservation error. Compared with the no-penalty recommendation, it achieved 5.3% lower error and 2.6% lower complexity. At β = 1, final error was about 6.5 times the β = 0.1 error. The best initial run retained the lowest error.

Reproduce the cost-aware results

To check the two published reductions, download reproduce_cost.py and measured_costs.csv into the same folder. Both files ship under examples/hydrodynamics/paper_comparison/ in v0.5.1. From that folder, run:

python reproduce_cost.py
Sedov: 558,284 -> 252,890 (54.7% lower)
Rotating cylinder: 3,427,030 -> 2,672,995 (22.0% lower)

The script reads measured refinement complexities and computes 100 × (1 − selected/reference). For Sedov it compares the β = 1 and β = 0 final simulations. For the cylinder it compares the β = 0.1 final simulation with the lowest-error initial simulation. These are single-simulation costs. The script checks the arithmetic without running Enzo.

What ships in v0.5.1? The tag contains Sedov β = 0 and 1 settings with the reported final measurements. Its cylinder β = 0 and 1 files describe an earlier ten-initial-run design. The paper used five initial runs and also tested β = 0.1. The tag lacks that configuration and a command to regenerate the paper’s cylinder search. Fresh forward simulations require the corresponding Enzo setup. The tagged release includes the script and measured rows for both percentage comparisons. Inspect the tagged settings.

Limits, FAQ and citation

Interpret each result in the context of its simulator, data, and run budget.

  • The reported adaptive searches are individual runs per configuration. The SAGE comparison includes three Latin hypercube controls and uses the small mini-Millennium merger trees.
  • The learned distribution is a calibration density shaped by the explored simulations. The study does not propagate observational errors or infer a Bayesian posterior.
  • Compare final_recommendation with best_observed. An earlier simulation may have a lower loss.
  • Fresh hydrodynamic simulations require Enzo and the case setup. Fresh galaxy simulations require SAGE and merger trees. The archived SAGE replay needs only the released software and bundled outputs.

Frequently asked questions

My simulator crashed. What happens?

The CLI stops and reports the evaluation number and inputs. Completed evaluations are flushed to evaluations.jsonl. Inspect the simulator’s standard error, fix the adapter, and rerun in a new directory. To reuse completed evaluations, convert their inputs and outputs to the initial CSV format.

What if the loss stops improving?

Inspect the individual outputs of your best run first. Check their units and target IDs. If the best inputs sit on a bound, reconsider the physically plausible range. If the initial sample leaves much of that range uncovered, consider more initial simulations or more adaptive rounds. An exploratory step can have higher loss than the preceding run.

Can simulations run in parallel?

The v0.5.1 local CLI waits for one simulator call to finish before choosing the next point. Your adapter can launch a parallel simulator and wait for its result. You can also generate the initial simulations separately in parallel and import their completed rows.

How does this compare with Bayesian optimization or simulation-based inference?

Bayesian optimization typically models a scalar objective and uses an acquisition rule to decide where to evaluate it next. Here the flow learns from simulation inputs paired with their output profiles and proposes parameters for a specified target. Both approaches can guide sequential experiments. Simulation-based inference often aims to quantify posterior uncertainty under a prior and an observation model. This workflow uses its density to guide a search and checks its recommendation in the simulator.
